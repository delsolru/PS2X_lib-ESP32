## Что изменилось

### Почему оригинал 1.9 не работает на ESP32

| Код оригинала | Что происходит на ESP32 |
|---|---|
| `#include <avr/io.h>`, `SREG`, `cli()` | файла и регистров не существует → **ошибка компиляции** |
| `portOutputRegister()`, `digitalPinToBitMask()`, арифметика `_lport + 1/+2` | есть только в AVR/PIC32 → ошибка компиляции или запись в чужие регистры |
| `byte`, `boolean` в публичном API | зависят от typedef-ов конкретного ядра |
| `bitSet()` | макрос AVR-ядра, в ядре ESP32 отсутствует |
| `pinMode(dat, INPUT)` + `digitalWrite(dat, HIGH)` (включение подтяжки) | на AVR так включается подтяжка; на ESP32 `digitalWrite` на входе — **ничего не делает** → DAT «в воздухе», читается мусор |
| `delayMicroseconds(4)` для шины | на ESP32 внутри крутится `esp_timer_get_time()`: дорого и с большим джиттером на 1–5 мкс — ровно в окне бита PS/2 |
| `readType()` безусловно печатает в `Serial` | ломает вывод прикладного скетча |
| нет проверки пинов | GPIO 6–11 занят SPI-flash, 34–39 — только вход: библиотека молча «не находит» геймпад |

### Что сделано в этом издании

1. **Переносимая прослойка GPIO.** Абстракция `PS2X_HwPin` с тремя реализациями:
   регистры AVR `PORTx/PINx` (без изменений, скорость как у оригинала), регистры
   ESP32 `GPIO_OUT_W1TS/OUT1_W1TS` + `GPIO_IN/IN1`, и обычные
   `digitalWrite()/digitalRead()` для всего остального (ESP8266, RP2040, SAMD, …).
   Фронт CLK — одна запись в регистр, поэтому тайминг шины не зависит от CPU.
2. **Настоящие микросекунды на ESP32.** Задержки считаются по счётчику тактов
   CPU (`esp_cpu_get_ccount()`), то есть в тактах, а не в вызовах функций;
   калибровка автоматически следует за `setCpuFrequencyMhz()`.
3. **Тот же протокол и тот же API.** Порядок бит-бэнга, слот ACK, байты команд,
   логика повторов, рост `read_delay` — всё оставлено как в 1.9. Старые скетчи
   компилируются без правок (см. «Совместимость»).
4. **`INPUT_PULLUP` на DAT**, проверка корректности пинов с отдельным кодом
   ошибки (`PS2X_ERR_BAD_PIN`) вместо молчаливого отказа.
5. **Диагностика**: `lastError()`, `ok()`, `failedReads()`, `frameMicros()`,
   `debugPrint(Print&)`, `errorText()`, `typeText()`.
6. **Восстановление hot-plug**: если 500 мс нет валидных кадров — полная
   инициализация запускается заново, геймпад можно отключить и подключить без
   перезагрузки.
7. **Подстройка на ходу**: `setTiming(clkLow, clkHigh, byteGap)` и `setReadDelay()`
   для длинных проводов и капризных приёмников 2.4 ГГц.
8. **Без «мусорного» состояния**: при сбое кадра состояние кнопок не обновляется,
   а первый хороший кадр после переподключения не рапортует о «только что
   нажатых» зажатых кнопках.
9. **`read_gamepad()` теперь возвращает `bool`** (было `void`), так что можно
   писать `if (!ps2x.read_gamepad()) …`; старый код, игнорирующий результат,
   компилируется по-прежнему.
10. **Документация**: этот файл, `README.md`, `CHANGELOG.ru.md`, `CHANGELOG.md`,
    `library.json` для PlatformIO, полный текст GPLv3.

## Совместимость

* Тот же заголовок `PS2X_lib.h`, тот же класс `PS2X`, те же имена методов и
  констант — скетч, написанный под PS2X_lib 1.9, компилируется без единой правки
  (проверено специальным «олдскульным» скетчем с `byte`, `boolean`, `int error`
  и обеими формами `config_gamepad()`).
* Перед установкой удалите старую `PS2X_lib`: оба варианта предоставляют
  `PS2X_lib.h`, и IDE придётся выбирать.

## Подключение

```
     ресивер PS2 / геймпад             ESP32            Arduino UNO
     ----------------------           -----            -----------
     DAT  (data)                     GPIO27             D13
     CMD  (command)                  GPIO23             D11
     ATT  (attention / select)       GPIO19             D10
     CLK  (clock)                    GPIO18             D12
     VCC                              3.3V               3.3V
     GND                              GND                GND
```

* **Питание — 3.3 В.** Практически все приёмники (включая дешёвые «беспроводные»
  клоны) работают от 3.3 В; проводной DualShock 2 тоже, только вибрация слабее.
* **DAT — это вход ESP32**, а входы ESP32 не переносят 5 В. Если ваш приёмник
  действительно выдаёт 5 В на DAT — делитель (2.2 кОм + 3.3 кОм) или level
  shifter. 5 В прямо в GPIO сжигает пин.
* Если DAT нестабилен — внешняя подтяжка **4.7–10 кОм к 3.3 В** (внутренняя у
  ESP32 около 45 кОм).
* Общий GND обязателен. Провода — короткие, лучше витая пара; 150 кГц по 30 см
  «соплей» уже сбоят.
* Беспроводной приёмник: сначала **сопрягите** его с геймпадом (кнопка на
  приёмнике), потом включайте ESP32; в скетче дайте `delay(300)` перед
  `config_gamepad()`.

Пины ESP32, которые **нельзя** использовать:

| Пины | Почему |
|---|---|
| 6–11 | подключены к SPI-flash |
| 34–39 | только вход (годятся для DAT, не для CLK/CMD/ATT) |
| 0, 2, 12, 15 | «strapping» — меняют режим загрузки |
| 1, 3 | UART0 (`Serial`) |
| 16, 17 | заняты PSRAM на платах WROVER |

Набор по умолчанию в примерах: **CLK=18, CMD=23, ATT=19, DAT=27**.

## Установка

### Arduino IDE 2.x
1. Удалите старую `PS2X_lib` (оба варианта дают `PS2X_lib.h`).
2. Установите это издание любым способом:
   * `Sketch → Include Library → Add .ZIP Library…` с `PS2X_lib-2.0.0.zip`
     со [страницы релизов](https://github.com/delsolru/PS2X_lib-ESP32/releases);
     «Code → Download ZIP» с GitHub тоже подходит (IDE сама переименует папку);
   * `git clone https://github.com/delsolru/PS2X_lib-ESP32.git Documents/Arduino/libraries/PS2X_lib`;
   * либо просто скопируйте папку репозитория в `Documents/Arduino/libraries/`.

## Быстрый старт

```cpp
#include <PS2X_lib.h>

PS2X ps2x;

void setup() {
  Serial.begin(115200);
  delay(300);                                    // приёмнику нужно время на старт

  uint8_t err = ps2x.config_gamepad(18, 23, 19, 27, false, false);
  //                              CLK CMD ATT DAT
  Serial.println(PS2X::errorText(err));          // "ok" или причина
}

void loop() {
  if (!ps2x.read_gamepad(false, 0)) {            // малый мотор, большой мотор 0..255
    delay(100);
    return;
  }

  if (ps2x.Button(PSB_START))        Serial.println("START");
  if (ps2x.ButtonPressed(PSB_CROSS)) Serial.println("X");

  int lx = ps2x.Analog(PSS_LX);   // 0..255, в покое ~128
  int ly = ps2x.Analog(PSS_LY);
}
```

## API

### Как в оригинале (не изменилось)

| Метод | Смысл |
|---|---|
| `uint8_t config_gamepad(clk, cmd, att, dat, pressures=false, rumble=false)` | инициализация; 0 при успехе |
| `bool read_gamepad()` / `bool read_gamepad(bool motor1, uint8_t motor2)` | прочитать кадр; `motor1` — малый мотор вкл/выкл, `motor2` — сила большого 0..255 |
| `bool Button(uint16_t)` | нажата **любая** из переданных кнопок |
| `bool ButtonPressed(uint16_t)` / `ButtonReleased(uint16_t)` | только что нажата / отпущена |
| `bool NewButtonState()` / `NewButtonState(uint16_t)` | состояние изменилось (любой кнопки / этой) |
| `unsigned int ButtonDataByte()` | инвертированное 16-битное слово кнопок |
| `uint8_t Analog(uint8_t)` | стики `PSS_LX/LY/RX/RY`, кнопки с давлением `PSAB_*`, `WHAMMY_BAR` |
| `uint8_t readType()` | 1 DualShock, 2 Guitar Hero, 3 беспроводной, 4 DualShock в цифровом режиме, 0 — неизвестно |
| `void enableRumble()` / `bool enablePressures()` | включить на ходу |
| `void reconfig_gamepad()` | переслать конфигурацию |

### Новое в 2.0

| Метод | Смысл |
|---|---|
| `lastError()`, `ok()`, `connected()` | код последней ошибки / валиден ли последний кадр |
| `failedReads()`, `lastOkAge()`, `lastReadAge()` | качество связи |
| `frameMicros()` | длительность последнего вызова `read_gamepad()`, мкс |
| `setTiming(clkLow, clkHigh, byteGap)` | тайминг шины в мкс |
| `setReadDelay(ms)` / `readDelay()` | минимальный интервал между кадрами (1..10 мс) |
| `setAutoReconnect(bool)` | авто-переинициализация (включена по умолчанию) |
| `rawPacket()`, `rawPacketSize()` | сырой 21-байтовый ответ |
| `debugPrint(Print&)` | дамп состояния одной строкой |
| `PS2X::errorText(code)`, `PS2X::typeText(type)` | текст для человека |

## Как это работает внутри

* **Тактированием управляет хост.** Библиотека сама генерирует CLK и знает, когда
  читать DAT, поэтому прерывания (Wi-Fi, BT, таймеры) **не нужно** отключать:
  запись в регистр GPIO — одна атомарная инструкция, а если прерывание всё же
  растянет фазу такта, данные не испортятся — контроллер меняет DAT только по
  фронтам, которые генерируем мы.
* Побитый кадр отбраковывается по байту режима (`0x7x` = аналоговый), библиотека
  делает до 5 попыток.
* **Тайминги по умолчанию**: 4 мкс низкий + 2 мкс высокий + 3 мкс пауза между
  байтами → SCK ≈ 166 кГц (интерфейс PS/2 допускает до 250 кГц). Кадр из 9 байт ≈
  **0.45 мс**, полный 21-байтовый (с давлениями) ≈ **1.05 мс**.
* **Восстановление**: если 500 мс нет валидных кадров, инициализация выполняется
  заново. Если библиотеку не опрашивали 1.5 с, контроллер уходит в «цифровой»
  режим — это распознаётся и конфигурация пересылается (как в оригинале).

## Подстройка

Некоторые дешёвые беспроводные приёмники не держат 150 кГц. Признаки: ошибка 1
или 2, либо валиден каждый второй кадр.

```cpp
ps2x.setTiming(6, 3, 5);   // медленнее и надёжнее (у AVR-оригинала ≈ 4/1/3)
ps2x.setTiming(2, 1, 2);   // быстрее — только для коротких проводов
ps2x.setReadDelay(4);      // не чаще одного кадра за 4 мс
```

Отладочный вывод (с текстом ошибок, в отличие от оригинала):

```cpp
#define PS2X_DEBUG      1   // перед #include <PS2X_lib.h> — setup/ошибки
#define PS2X_COM_DEBUG  1   // побайтовый лог обмена (очень многословно)
```

Раскладка сырого пакета (`rawPacket()`, то есть `Analog(i) == rawPacket()[i]`):

| Индекс | Содержимое |
|---|---|
| 0 | 0x01 (заголовок) |
| 1 | режим: `0x73` аналог / `0x79` аналог + давления / `0x41` цифровой |
| 2 | 0x5A (всегда) |
| 3–4 | кнопки, младший/старший байт (инвертированные) |
| 5–8 | RX, RY, LX, LY |
| 9–20 | давления (только при `pressures = true`) |

## Коды ошибок

| Код | `errorText()` | Что делать |
|---|---|---|
| 0 | ok | всё хорошо |
| 1 | no controller / invalid frame | питание 3.3 В, GND, правильные пины, сопряжение приёмника, подтяжка DAT, `delay(300)` в setup |
| 2 | controller refuses configuration | геймпад отвечает, но не принимает команды: обычно слишком быстрая/грязная шина → медленнее `setTiming()`, короче провода |
| 3 | no pressure support | геймпад не поддерживает давления — вызовите `config_gamepad(..., false, ...)` |
| 4 | invalid pin assignment | GPIO 6–11, входной пин на выход или несуществующий пин |
| 5 | config_gamepad() not called | вызовите `config_gamepad()` в `setup()` |

## Примеры

| Пример | Для чего |
|---|---|
| `PS2X_Example` | полный демо-скетч (как в оригинале: кнопки, стики, Guitar Hero, вибрация) |
| `PS2X_ESP32_Diagnose` | **начните с него**: печатает ошибки, тип геймпада, время кадра, качество связи; команды `c/d/r/s/f/?` (переинициализация, дамп, тест вибрации, медленнее/быстрее) |
| `PS2X_Minimal` | минимальный скетч + пересчёт стиков в «танковое» управление −100..+100 |
| `PS2X_TankDrive` | два коллекторных мотора (L298N / L293D / TB6612): танковое смешивание, мёртвая зона, ограничение ускорения, триггер скорости на L2/R2, аварийный стоп, моторы встают при потере связи |
| `PS2X_ServoPanTilt` | панорама/наклон камеры или плечо манипулятора: правый стик *задаёт скорость* сервоприводов (а не абсолютный угол), возврат в центр по TRIANGLE, медленный режим по SQUARE — на ESP32 работает без библиотеки Servo (через LEDC) |
| `PS2X_Calibrate` | измеряет min/max/центр и мёртвую зону по каждой оси стика и сохраняет в EEPROM (AVR) / NVS (ESP32); внутри — готовый хелпер «сырое → −1000..+1000» |
| `PS2X_Telemetry` | поток 50 Гц в машинно-читаемом виде: CSV для таблиц/графиков или JSON для скриптов, вместе с качеством связи (`ok`, `fails`, время кадра) |
| `PS2X_DualControllers` | два геймпада на одном MCU (два приёмника): первый ведёт робот, второй управляет манипулятором/башней; отсутствие одного не мешает второму благодаря hot-plug |
| `PS2X_PressureRumble` | кнопки с давлением (21-байтовый кадр) и виброотдача от триггеров L2/R2; корректно откатывается к «обычным» кнопкам |

Все примеры написаны и под ESP32, и под AVR (таблицы пинов — в шапке каждого
скетча) и используют только библиотеки, входящие в ядра.

## Что проверено

Собрано через arduino-cli (инструменты Arduino IDE 2.x), без ошибок и без
предупреждений из кода библиотеки. Каждый push и pull request пересобирается в
GitHub Actions (.github/workflows/build.yml: arduino-lint + матрица ниже):

* **ядро ESP32 Arduino 2.0.8** — все девять примеров на `esp32:esp32:esp32`;
  дополнительно проверены на `esp32s3` и `esp32c3` те скетчи, где есть
  платформозависимый код (моторы, сервоприводы, EEPROM, телеметрия, два геймпада);
* **ядро AVR 1.8.6** — все девять примеров на `arduino:avr:uno`; дополнительно
  `nano`, `mega`, `leonardo`;
* варианты сборки: `PS2X_FORCE_SOFT_GPIO`, `PS2X_DEBUG=1`, `PS2X_COM_DEBUG=1`,
  `PS2X_SKIP_PIN_CHECK`, а также «олдскульный» скетч в стиле PS2X_lib 1.9 без
  правок.

Проверка на железе (это уже за вами — со сборочной машины не сделать):

1. `PS2X_ESP32_Diagnose` → `config_gamepad() -> 0 (ok)`, `controller type: DualShock`;
2. нажатия меняют `buttons 0x…`, стики плавно идут 0..255 (в покое ≈128, на краях 0/255);
3. `frame=…us` стабильно (±20 %), `fails=0`;
4. отключите и подключите геймпад — связь возвращается за ~0.5 с;
5. команда `r` — вибрация, если поддерживается.

Если что-то не так: сначала `s` (медленнее шину) в диагностическом скетче, затем
внешняя подтяжка 4.7 кОм на DAT, затем питание.

## Ограничения

* Аппаратный SPI/DMA не используется: протокол PS/2 требует ACK по каждому байту и
  тактирования от хоста, поэтому шина бит-бэнгится (как в оригинале).
* Два геймпада — два объекта `PS2X` на **разных** пинах (на одной шине PS/2 два
  геймпада не работают).
* Не совместимо с `light sleep` / агрессивным энергосбережением — теряются
  тайминги шины и подтяжки (для обычных роботов это неактуально).
* Guitar Hero — как в оригинале (тип 2); давления — только на совместимых
  DualShock.
